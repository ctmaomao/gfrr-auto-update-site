# OFR 观察日连续性修复 · 2026-11-09

## 验收基线和发现

本轮目标是持续审查金融状态读数与预测证据的可靠性，优先落实可复现、可验证的小修复，不扩张页面、来源或付费调用。基线为 main `9641f7b1eedfa1487ad8117347e97d2413e1b6bf`，使用独立工作树，保留原有任务。

OFR 当前是主压力读数，旧六模块分数仅作审计。发布路径以前只验证新文件自身的日期和七日年龄，没有与上一发布的观察日比较。合成复现：上一发布观察日 2026-11-05、值 2；新收到的文件截断至 2026-11-04、值 -1。两者均在七日内，旧代码会发布更早的 -1，并标记 `available/currentEligible=true`，造成无证据的当前压力下降。该示例是离线测试，不是实际 OFR 数据，也不表示已经发生线上回退。

## 最小修复

只修改 `scripts/daily/publish-ofr-pressure.mjs` 的现有发布编排：

- 新来源通过既有契约后，比较最新观察日与已通过既有验证的上一组件。
- 日期倒退时复用既有失败缓存路径，保留上一观察、历史、周差、百分位、原收据和哈希，记录 `ofr_observation_date_regressed`，不授予当前资格。
- 连续失败仍使用原观察日计龄，超过七日为 stale，不用新抓取时间续期。
- 同日官方修订、新日观察、真实零与显式缺失继续按原契约处理。较新缺失不能被较旧有限数值替代。
- 没有有效历史组件时允许正常首发。没有重试、额外网络调用、生产 JSON 编辑、评分/阈值变化、前端变化或既有 checker 断言修改。

日期倒退也可能是官方撤回或更正，而不是传输故障。现阶段不能自动判定其原因，因此只保留有原日期的旧缓存并退出当前资格，不能把旧值说成当前真值。后续正常响应恢复后自行恢复既有发布流程。
