## 3. 跨上下文诊断（单列，不计入确认缺陷）

按试点方案的约定，环境配置或跨上下文造成的诊断必须单列。

| 项 | 值 |

| `no-undef` 总数 | 31 |

**31 项全部是 `tests/e2e/*.spec.mjs` 中 Playwright **浏览器求值回调**内的浏览器标识符**（`document`、`window`、`getComputedStyle`、`innerWidth`）。这些回调由 Playwright 序列化后在**浏览器上下文**执行，而 ESLint 按 spec 文件的 Node 环境静态分析，因此必然报告未定义。

回调形式实测归属（31 项全部有归属，无未归属项）：

| 求值形式 | 项数 |
|---|---|
| `page.evaluate()` | 19 |
| `locator(...).evaluate()` | 12 |

**结论：这 31 项不是缺陷，是已知的静态分析局限。** 按方案约定，它们**不计入"确认缺陷"数量**，并作为**独立类别**单列（不与其他类别混称）。

关于环境隔离：本报告**不**以"零诊断"论证隔离生效——**零诊断不能证明不存在未定义引用**，只能说明在当前配置与扫描范围内未发现 `no-undef` 诊断。环境隔离由配置层面的检查支持：`--print-config` 实测确认 Node 文件得到 81 个 globals 且不含 `document`，browser 文件得到 1204 个且不含 `process`，Worker 文件得到 347 个且不含 `process`/`document`（见第 6 节）。

`_` 前缀是**统计特征**，不是判定结论：命名只能表明意图，不能代替逐项核对。因此这 43 项**归入"待判断"**，而非"有意用法"。

需要区分两个独立判断：

1. **项目是否采用 `^_` 忽略约定**（配置决策，见第 5.1 节）
2. **这些绑定是否确实有意未使用**（逐项代码判断，本报告未做）

### 4.2 no-dupe-keys（1）—— 已确认的重复键问题

```
scripts/replay-transport-shock-confirmation-factor-free-proxy-score-candidate.mjs:260
  Duplicate key 'inputStatus'.
```

已打开核对：同一对象字面量中 `inputStatus` 在 **L255 与 L260 各出现一次**，且**两处值相同**（均为 `candidate.status`），后者覆盖前者。

准确表述：**已确认存在重复键；尚未证明造成输出错误**（因两值相同，覆盖不改变结果）。该问题在**现有 `node --check` 中未报告**——这是相对现有语法检查的增量发现，但"语法分析无法发现"不宜表述为绝对（不同工具能力不同）。

## 6. 复现方式

```powershell
npm run lint
# 或机器可读：
npx eslint --no-config-lookup --config eslint.config.mjs --format json scripts tests workers
```

配置要点（`eslint.config.mjs`）：

- 三套环境**范围互斥**：Node 块显式排除 `scripts/app.js` 与 `scripts/modules/**`，因为 flat config 下多块匹配同一文件时 `languageOptions.globals` 是**合并**而非替换
- Worker 块使用 `globals.worker`（实测覆盖所需 9/9 个全局），**未**手工加入 `env`、`ctx`、`ExecutionContext`、`scheduled`——前者是函数参数、后者是类型名，加入会掩盖真实的未定义引用
- 规则集为 9 条正确性规则，**无任何格式/风格规则**
