# ADR-0112: Transitional Bubble receipt-based one-call grant

## Current storage supersession

[ADR-0113](0113-private-bubble-claim.md) supersedes this document’s proposed public whole-ledger initialization and outcome storage for the fixed selection. That initialization was not executed. Historical accounting and candidate review protections below remain, but no private evidence may be posted as a public ledger.

## Scope and status

2026-11-12 owner requests one Bubble DeepSeek call, factual review before publication, and identification of the website API key. Combined website editorial spending remains capped at CNY 10 for the current project calendar month; Tavily and Brave remain free-only. Subsequent clarification requires a website-key-specific long-term budget rather than charging unrelated account keys against it. This implementation is local preparation, not paid execution, ledger initialization or publication approval evidence. Independent exact-diff review and normal checks remain required.

## Separate accounting and authorization

The fixed `editorial-bubble-receipt-20261112-v1` grant is manual Bubble-only, one attempt total, no retry, no renewal, and at most 24 hours from its reviewed snapshot. It cannot activate Macro or recurring monthly accounting. Its independent create-only branch is `deepseek-bubble-receipt-20261112`; genesis is pinned with the approved main parent. Old monthly and both one-shot validators, policy/grant digests, consumed slots and permanent reserve/outcome entries are unchanged.

The private snapshot embeds the two authenticated legacy ledgers, their exact heads/genesis anchors/digests and common key fingerprint. Completed receipt tokens are conservatively valued at independently verified peak prices of 2 and 8 micro-CNY/token; these bounds are not actual monetary settlement. The whole-account period subtotal rounds upward to micro-CNY. Three earlier authenticated HTTP200 responses add their receipt bounds regardless of subsequent article validation failure. One earlier completed call lacks retained token usage and therefore retains a full-context allowance. Admission deliberately adds the export, all receipt bounds and that missing-usage allowance, including their overlap, then reserves one new full-context call within the CNY10 cap. Actual account amounts, token counts and run identifiers remain in the independently reviewed private record rather than public code or this operational document. No overlapping spend is subtracted, no old reservation is refunded, and no slot is restored.

This ADR narrowly supersedes the inference that permanent historical authorization reservations must also be the only possible historical-liability estimate for every new grant. It does not change ADR-0110's actual ledger records or ordinary monthly admission. The export is a deliberately conservative once-only historical ceiling, not website actual spend, not proof that all account usage belongs to the website, and not a recurring all-account budget. Future key-specific accounting needs its own reviewed design.

## Evidence and calendar

The independently approved grant digest covers the complete snapshot and authorization evidence. `authorizedAt` records the real owner message time, which may precede subsequent evidence observation; the current independent price review must be verified at or after both timestamps. Snapshot age and expiry are measured from evidence observation, never by inventing a later authorization time. The fixed project month is November 2026, with project UTC offset fixed to zero. It is not called the vendor billing calendar. Export buckets are displayed at UTC+13; retain the entire bucket intersecting the project month start and the observed current bucket. Coverage endpoints must come from the actual selected export range, including empty buckets; never invent a later endpoint from nonempty rows. The current bucket is an as-of observation, not proof of settled future usage. Account scope/export, full November workflow inventory and quiescence evidence digests are required. Four early completed records bind exact run IDs, completion times and evidence hashes; three contain verified token receipts and the fourth explicitly uses a full unknown-cost completed allowance. Missing usage must not be silently zeroed. Unknown requests or uncontrolled project paths hold initialization/admission; a boolean alone without reviewed evidence is not a valid operator attestation.

Quiescence evidence covers identified project callers: the complete GitHub run inventory, rejected direct/manual consumers under the shared gate, absent monthly ledger and consumed legacy grants. It is a practical review of known authorized project paths, not an assertion that no person could run copied or modified code elsewhere. At preflight and again at paid admission/dispatch, authenticated bounded GETs require unchanged legacy heads and bodies, absent monthly ref, and no other queued/running/waiting/pending/requested editorial workflow. Failed, truncated or ambiguous reads hold. GitHub cannot exclude unobserved copied/modified-code activity outside the approved project paths; this is a disclosed limitation, not a fabricated universal-absence claim. Any actually identified additional project exposure must be reconciled before admission. The snapshot is not automatically refreshed and cannot be rewritten after initialization.

## Runtime and review

Runtime must be the first attempt of the Bubble manual workflow on main. It hashes the actual secret and requires the historical fingerprint before balance lookup or reservation. The separate offline diagnostic outputs only full SHA-256 and SHA-256 of the export-compatible first-eight/colon/last-four projection; it sends nothing to the provider. Unique observed-account masked-key matching identifies the displayed name practically, not with mathematical global uniqueness. Unknown/duplicate matches remain unknown.

Current reviewed prices, exact CNY balance, payload/model/usage validation, CAS reservation, trusted clock, failure retention and no retry remain mandatory. The new reservation persists even if dispatch exposure changes or generation fails. All factual, source, freshness and final-writer protections remain unchanged; a generated article is not automatically factually acceptable.

## Acceptance

Offline tests cover conservative arithmetic/rounding, unknown and altered evidence, wrong key/consumer/mode, expiry, immutable old ledgers, permanently consumed attempts, dispatch-time exposure changes and concurrent CAS. Live-verifier mocks cover changed heads, monthly presence, ongoing calls, truncated listings and untrusted clocks. Run focused budget/wiring/workflow tests, full `check:changed`, independent exact-diff review and later exact-head CI. The ordinary-route credential/receipt assertions remain intact. Narrow explicit assertions permit only the successful new-grant offline key scan and validated evidence artifact; no generic extra secret scope or raw artifact upload is allowed. No ignore list or dependency is added. Real evidence attestation, create-only initialization, production key matching and the single authorized call remain separate coordinator actions.

## Successful candidate-only review stage

For this exact new grant only, generation must stop before production writing and Git push. Existing structural validation, automated review and projection still run, followed by a separate successful-candidate packager. This narrowly supersedes ADR-0103's no-unsaved-text artifact rule only for an already validated successful candidate necessary for the owner's requested independent factual review before publication. Ordinary routes and rejected/failed generation receipt-only retention are unchanged.

The short-retention bundle contains only allowlisted validated editorial output and the original compact public-site source input/news excerpts required by the existing final writer. These are source evidence, not prompts, provider response envelopes or raw network responses. Retain exact source facts rather than silently rewriting them for sanitization. Bind the source commit, original run identity and input digest; cap bytes and scan against the actual provider key before packaging. Any schema failure, secret match or missing validation prevents retention. No credentials, headers, account/ledger exports or unrelated user data may be included. Retention is at most three days.

The bundle is not publication approval. Independent review must check claims, units, dates, source URLs and exact tracked source snapshot. A subsequent narrow, independently reviewed coordinator publication admission must authenticate the actual original GitHub run, retained artifact and source commit, and bind independent factual approval to the exact candidate digest. It may then invoke the existing `buildWeeklyEditorialWriteResult` with unchanged source and freshness checks, without a new provider call. This publication admission is a separate follow-on change, not implemented by staging. Do not forge `GITHUB_RUN_ID`, invoke the old CLI outside its original run, or claim an end-to-end release route exists before that admission is ready. If intervening source changes or freshness invalidate those gates, preserve the consumed slot and do not publish stale evidence or regenerate automatically. Candidate generation must never label the article saved or live merely because packaging succeeded.
