# GFRR 每周周报发布与归档

- 沿用既有周二 Pacific/Auckland 09:00 主发布、周三兜底安排，每周只出一期；不新增仓库定时器或重复任务。
- 规范正文路径为 reports/YYYY-MM-DD.html；每期完整UTF-8单HTML，样式和可选打印脚本内联，正文不请求实时数据。
- 新一期使用下方的原件保存与期次验收流程；生成器更新 weekly-reports.html（最新完整正文和近期目录）、reports/archive.html，以及 weekly-reports/index.html 和 weekly-reports/YYYY-MM-DD.html 旧路径兼容副本。
- 最近52期列在首页；更早期次只进入历史归档列表，固定URL、正文和Git历史保留。没有自动永久删除操作，也不因生成/发布失败清理任何旧文件。
- 历史日期页不得跟随最新数据重新计算或重写。必要纠错须明确版本与纠错说明；不静默改旧数值。
- 周报原件与站点外壳分开。历史周报链接与“下载单文件HTML”由 `weekly-reports.html`、`weekly-reports/index.html` 和 `reports/archive.html` 的统一操作栏提供，不要求原稿自带这两个控件。下载链接指向当期固定日期页，以 `GFRR_Weekly_YYYY-MM-DD.html` 保存验收原件的字节，而不是下载生成入口。操作栏和四标签沿用 DESIGN §4.5 的站点纸媒风格；冻结原稿既有排版、正文和可选打印不因站点样式差异而改写，两个日期页仍与原件逐字节相同。
- 编辑核对参见[四项容易混用的来源](EDITORIAL-SOURCES.md)；该清单不改变生产取数，也不是自动发布门槛。
- 正文面向金融初学者和普通读者。开头给一句本周判断和三条要点；每节讲清发生了什么、为什么重要、接下来观察什么。术语首次出现时用一句白话解释，区分事实、推断和情景。
- 重要事实链接具体发布、表格或系列。推算数字说明口径；不混用 Brent 现货、期货或不同合约收益率。后台仍逐项记录观察、发布、获取时点，未知保持未知，并保存缺项与部署核验；仅当证据局限会改变读者对结论的理解时，在相关段落简短说明。
- 旧GFRR模型分、作者研究分和现行OFR原始指数必须区分，不换算为危机概率。事实、推断、情景与来源局限分别披露。没有可核对的前周同口径数据就不发布周差。
- 首页右上四个常显标签；根入口默认周报，全球雷达使用 index.html?view=radar，原雷达锚点保持兼容。
- 发布前运行 check:changed（完整check:all）、周报路由与离线浏览器测试、Pages artifact和EdgeOne staging验证；浏览器测试从三个站点外壳验证下载文件名及原件字节，同时继续独立验证两个日期路由和离线正文。仅在授权并通过独立审阅后集成发布，随后实测两站首页、日期正文、四标签和旧锚点。
- 发布后提供 GFRR_Weekly_YYYY-MM-DD.html 原文件附件，并如实报告提交、CI与部署状态。未通过部署验证不得称已上线。

## 原件、构建与发布回读

1. 对已完成内容与来源验收的完整 UTF-8 HTML，在原始文件上计算 SHA-256，独立记录预期期次日期和摘要。标题必须标识期次日期。原件与每个生成页均不得超过 2 MiB（按 UTF-8 字节计），生成前检查；完整性由验收原件及其摘要共同约束；摘要只能证明字节一致，不证明事实准确或来源已核查。原件不在时停止，不由摘要或旧期重建正文。
2. 生成并验收原稿后，先执行 `node scripts/weekly-remote-handoff.mjs save YYYY-MM-DD SHA256 /path/to/accepted.html`，只使用现有 GitHub 写入能力，将原件及身份文件作为单一提交存到该期专属分支 `weekly-originals/YYYY-MM-DD`，随即重新获取并校验字节、日期和摘要。该分支不触发网站发布；命令不会覆盖不同原件，并在每次网络操作前检查 Git 实际 fetch 和 push 端点均为指定 GitHub 仓库，拒绝 URL 重写。分支可被有权限的主体修改或删除，并非不可删除存储；后续会核对固定提交与摘要，分支消失或变化时停止。相同原件可恢复重试。推送结果不明时检查远端，未能确认则停止，不盲目重复推送；不添加凭据。原件、生成页及尺寸预检通过后才能占用期次。
3. 在基于 latest main 的任务分支执行 `node scripts/weekly-original.mjs prepare YYYY-MM-DD SHA256`：从远端重新取回原件并校验，记录明确的预期期次、摘要和远端提交，再写入固定日期页并生成入口。重试必须使用相同日期和摘要；再执行 `node scripts/weekly-original.mjs check YYYY-MM-DD SHA256`，确认远端原件、身份和生成入口一致。新期的常规完整检查也要求预期身份文件及相同远端回读；它会批量核验所有非历史例外期次，交接分支不可读或网络不可用时检查失败，相关部署须等待恢复；但不能仅凭检查现有文件推断外部计划应有哪一期，定时任务必须传入实际预期期次与摘要。缺失、错期或摘要不符即停止。日期兼容页不覆盖，发生冲突应保留文件并调查，不自行删除历史。完整检查还会对照可信历史锚点及其首父提交链的日期页、兼容页和原件，拒绝删除或同路径替换；修订应使用明确版本化的新路径并另行评审。浅克隆无法完成该检查。
4. 运行完整检查、浏览器测试和 Pages/EdgeOne staging 验证，按 serial trunk 策略仅提交本期文件并经独立审阅；在 PR 中记录远端原件分支和提交，待独立审阅后再按既有发布流程集成。恢复时先读取并校验远端原件、分支与已有提交，不重新生成正文；CI 或部署失败保留原件和提交，修复后从失败阶段继续。仅有保存或构建成功不能称发布成功。
5. 集成并确认部署后，以实际发布的源码完整 commit SHA 执行 `node scripts/verify-weekly-publication.mjs YYYY-MM-DD SHA256 SOURCE_COMMIT`。脚本分别读取 Pages 与 EdgeOne 的日期页、兼容日期页、最新入口、兼容入口及历史入口，将每份字节与该提交逐一比较，并核对最新与历史入口的链接。保留输出的各 URL 与 SHA-256、比较用源码提交、两站部署及 CI 记录。输出仅证明各页面与该提交字节一致，不证明站点运行该提交。要声称部署来源，还须分别核验 Pages 实际部署检出的 source SHA，以及 EdgeOne 发布工作流的 source SHA、release SHA 和该 release 的实际构建；Pages 可能检出较新的 main。来源证据缺失时只报告字节一致。任一站点、链接或哈希失败即未完成发布，待修复后重试；实站四标签和旧锚点仍按上方浏览器验收。该步骤不会部署、触发付费服务或修改内容。

**接线状态：** 已核对既有定时任务配置：同一任务在 Pacific/Auckland 周二 09:00 主发、周三 09:00 仅为同一期兜底，要求远端保存及独立回读、显式期次/摘要和双站验收。下一次待验与上一期实况见[当前工作表](../docs/PROJECT_BACKLOG.md#active-worktable)；已接线不等于自然运行成功。仓库命令不会修改调度；缺回执或任一站未验收不得报成功。

## 同一期修订与回滚边界

- 无后缀日期仍表示第 1 版，路径不可覆写或改成跳转；修订使用同一期次日期和独立身份 `YYYY-MM-DD-r2`（后续版按顺序增至 `r99`，不得跳过前驱）。获批准后让修订稿标题写明原期日期和“第2版”，并在正文区分实际封版日及各数据观察期。不得以另填日期绕开前驱和摘要校验。
- 已交接但未发布的旧稿只保留原远端交接，不把它补进站点或目录。修订保存需明确提交本版 SHA-256、前一版 SHA-256 和前一版完整交接提交。新交接占独立同级分支 `weekly-originals/YYYY-MM-DD-r2`；先回读前驱，正常非强制推送只创建新分支，冲突或结果不明时只认可相同身份和相同字节的远端回读。已有无后缀旧分支不会移动；没有完整远端交接的历史例外版不能当作已验证前驱。
- 保存示例：`node scripts/weekly-remote-handoff.mjs save YYYY-MM-DD-r2 SHA256 /path/to/accepted.html PREDECESSOR_SHA PREDECESSOR_COMMIT`。独立保留保存回执；后续修订的 `prepare` 和 `check` 显式传入 `YYYY-MM-DD-r2 SHA256 HANDOFF_COMMIT PREDECESSOR_SHA PREDECESSOR_COMMIT`，不能从待核验分支推断预期身份。发布回读仍以版号期次、摘要和源码提交为输入。构建和完整检查继续拒绝缺失、错期、错误摘要、被替换的交接/前驱或覆盖固定历史。本地 `save`/`install` 不能替代远端验证。当前流程不接受给已经不是最新一期的期次补刊；如要支持往期修订应另行评审。
- 文档真实 `head` 的唯一标题使用“全球金融系统性风险周报｜日期”，修订版追加“｜第N版”（第 2 版可加“（首次修订）”）；日期可写 ISO 或“2026年11月9日”，保留既有 GFRR 刊头写法。裸日期身份不能接受修订文案；文章标题和摘要写在正文或说明元数据，不写入期次标题。只接受明确的 `head`、元数据、内联样式与正文边界，不从注释、模板、脚本或 SVG 取身份；可选打印脚本保留在正文。
- 一个工作区仅允许一个 `prepare` 更新当前身份和生成入口。并发请求遇到 `weekly-originals/.prepare.lock` 即停止，等待正常完成后再重试；如进程异常中止留下锁，应先核实锁内 PID、工作区和 CI 没有运行中的准备，再隔离遗留锁并用相同预期身份恢复。不能通过移除仍在使用的锁覆盖新版清单。
- 发布固定页为 `reports/YYYY-MM-DD-r2.html`，兼容副本为 `weekly-reports/YYYY-MM-DD-r2.html`；两路和 `GFRR_Weekly_YYYY-MM-DD-r2.html` 下载都必须保留修订原件的全部字节。仅最新入口、历史目录和当前身份清单随发布更新；最近52期按期次日期计数，已公开的旧版继续保留原 URL 并列为被取代，未发布的旧版不列出。双站回读依旧要与精确源码提交逐页比对，浏览器验收应另确认目录和下载实际可用。
- 回滚不得删除或改写已公开版本，也不得将当前期指回旧稿。尚无修订公开时可以停用新修订写入；修订一旦公开，代码回滚仍须保留对其路径/身份/交接的读取、历史保护、构建、CSP 哈希与回读。优先修正前行或暂停部署，不向旧生成器回退并让修订路由从站点消失。
